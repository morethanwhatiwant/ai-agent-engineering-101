# 창립 단골과 직접 추천 프로그램

코드 구현 상태: 시장 운영 중. 신규 시장조사·원가 보호 구조는 MARKET_INTELLIGENCE.md 참고. 보상 지급 성공은 별도 검증이 필요하다.

## 정책과 고객 흐름

`referral_policy.json`의 초기 실험값: 창립 단골 30명, 고정 5% 할인,
추천 구매 최대 3%, 직접 추천인 크레딧 최대 2%(각 최대 1,000원).
추천 할인과 새 크레딧의 합계는 매입비 차감 마진의 25% 이내다.
이는 최적값이 아니며 보관비/미래 수요를 예측하는 정책도 아니다.
창립 할인은 마진으로 축소하지 않는다. 저마진 재고에서는 손실도 가능하다.
기준가는 동일 상태의 재고에 대해 모든 구매자에게 같으며 `stock_pricing.py`가 계산한다.
생활용품 A/B/C는 정가의 95/80/60%, 식품 A/B/C는 95/75/45%를 초기값으로 사용한다.
식품은 마지막 24시간 동안 위 가격에 `0.2 + 0.8 × 남은시간/24`를 곱해 추가 할인한다.
카탈로그의 shelf_hours가 있으면 현재 유통기한으로 등급 하락을 재계산한다.
만료되거나 등급/유통기한을 확인할 수 없는 재고는 견적을 거절한다.
등급 가격은 기준값이며 실제 셀러는 seller_strategy.sale_quote로 원가·할인·추천 보상을 반영한다. 기본 원가 8% 마진과 1% 보관료 여유를 지키고, 원가 이하 판매는 하지 않는다.
협상 중 가격이 더 내려가면 결제 합의 시 낮은 값을 적용한다. 이 비율은 검증할
초기 정책이며 수요 기반 최적 가격이 아니다. 회원 할인율 동결과는 별도 정책이다.
기존 크레딧과 창립 할인은 합산하지 않고 더 큰 혜택 하나를 적용한다.

1. 바이어가 SKU를 요청한다. 추천을 받았다면 `ref=REF-...`를 붙인다.
2. 제시된 최종 금액을 숫자로 보내면 서명 영수증과 잠정 회원키를 받는다.
3. 키트의 실제 결제가 공개 ledger에서 확인되어야 회원이 활성화된다.
4. 새 A2A 요청 `STATUS member=<비공개키>`로 공개 추천 코드를 확인한다.
5. 공개 코드를 포럼에 공유한다. 비공개 회원키는 절대로 게시하지 않는다.
6. 직접 소개받은 구매자의 첫 확인된 구매가 확정되면 6시간 관측 후 크레딧을 받는다.
7. 새 구매자도 자기 코드를 얻는다. A→B→C에서 C의 구매 보상은 B에게만 간다.

창립 단골 자격은 결제+거래 리뷰(별점 무관)+해당 settle 번호가 refs에 붙은
본인 buyer 포럼 글을 확인하고, 6시간 사후 확인 후 선착순으로 부여한다.
좋아요 또는 높은 별점을 요구하지 않는다. 후기 참여 혜택임을 공개하도록 안내한다.
창립 자격과 크레딧의 유효기간은 2026-11-17 23:59 KST까지다.
실행 후 정책은 SQLite에 동결된다. 기존 약속을 바꾸는 설정 변경은 오류로 차단한다.

## 실행과 포럼 게시

현재 폴더의 `agent.json` seller는 `referral_seller.py`로 연결했다.
키트 실행 시 셀러와 함께 읽기/캠페인 작업이 시작된다. 등록된 가게의 공개키가
로컬 shop_key.pem과 일치하고, Round 3 재고와 최신 장부 동기화가 확인되어야 게시한다.
초기 모집글을 shop 역할로 5분 간격, 최대 6회 `.market/outbox.jsonl`에 적는다.
키트가 실제 전송하며, 자동 재게시로 한도를 우회하지 않는다. 같은 outbox에 다른
게시자를 함께 실행하면 키트의 공통 5분 제한에 걸릴 수 있다.

게시하지 않고 셀러를 확인하려면 seller 명령에 `--no-post`를 추가한다.
동기화만 단독 실행하려면:

```sh
python referral_campaign.py --once --no-post
```

공개 키트 계약에는 seller 결제 후 hook이 없으므로 ledger를 페이지 단위로 읽는다.
우리 공개키에 연결된 URL, 개별 재고 unit, SKU, 금액을 모두 확인한다.
과거 터널 URL도 보존한다. 동일 결제 재처리는 보상을 중복 발급하지 않는다.
장부를 끝까지 읽지 못했거나 네트워크에 문제가 있으면 보상 확정을 미룬다.
이 셀러는 고장 보증을 제공하지 않는다. 환불 이벤트가 관측되면 unit으로 취소하며,
해석할 수 없는 환불 이벤트는 추측하지 않고 동기화를 중단한다.

## 중요한 범위와 한계

- 회원키는 **소지자 방식(bearer)** 이다. 시장 계정 로그인/소유권 증명이 아니다.
  키를 넘기면 다른 사람이 할인받을 수 있다. 키는 해시로 저장하며 영수증 artifact,
  광고, 서버 로그에는 넣지 않는다. 구매자 측에서 대화 전체를 게시하지 않아야 한다.
- 협상 중 인증된 buyer 정보가 없어서, 공개 추천 코드를 사용하는 사람의 첫 구매 여부를
  선결제 단계에서 증명할 수 없다. **즉시 추천 할인은 소액 공개 프로모션**으로 취급한다.
  결제 후 동일 buyer/자기 추천은 추가 추천 보상을 받지 못한다. GitHub owner를 여러
  buyer에 걸쳐 검증하는 기능과 Sybil 방어는 아직 없다. 신규 전용 할인이라고 홍보하지 않는다.
- 같은 buyer가 새 키를 여러 번 만들면 기존 활성 회원키만 인정한다. 키 복구 기능은 없다.
- 서명한 판매는 결제 여부가 불명확할 때 재고와 크레딧 예약을 유지한다. 현 키트에
  영수증 만료를 강제하는 계약이 없어서 시간만으로 예약을 해제하지 않는다. 장기간
  미결제 예약이 누적되면 별도 시장 상태 확인/복구가 필요하다.
- forum.json은 최신 100개뿐이다. 오래 오프라인이면 이전 후기가 누락될 수 있다.
- 상대 바이어가 PROGRAM/STATUS와 회원키를 사용할 수 있어야 참여한다. 자동 참여는 아니다.
- 기존 market_buyer.py는 보존하고 실행 설정을 buyer_r3.py로 교체했다.
  주문의 acceptable SKU를 보유한 최대 3개 가게를 비교하고, 정확한 SKU·서명·예산을 확인한다.
  식품은 사용 기한, 생활용품은 6시간 보증을 실제 checkout에서 검증하도록 요청한다.
  `.market/buyer.sqlite3`에 주문/협상/합의/결제/실제 품질 기록을 저장한다.
  재시작 시 같은 주문은 자동 재구매하지 않고, payments.jsonl로 결제를 대조한다.
  가격 참고는 최근 결제된 동일 가게·동일 SKU로 제한한다. 숫자 결정은 현재 규칙 기반이며
  LLM 판단을 호출하지 않는다. 불명확한 주문의 자동 복구, 지연 고장의 구매 귀속,
  다른 가게의 임의 추천 프로토콜은 지원하지 않는다. buyer_publicist가 같은 운영자임을 밝힌 광고와 시장 관찰 글을 buyer 전용 큐에 쓴다.
  시장 결제 성공 기록은 buyer.sqlite3에 저장된다. 새 로직의 수익 개선은 실제 운영 데이터로 후속 검증해야 한다.
- 시장 사이트 자체에 공식 배지를 추가하지 않는다. STATUS의 founder 상태가 자체 배지다.

## 테스트

```sh
python -m unittest test_referral_program test_referral_seller -v
```

직접 추천 체인, 결제 검증, 낮은 별점 리뷰 인정, 실서버의 enriched refs 형식,
자기 추천/중복 계정 보상 차단, 환불 취소, 재시작 이후 이중 사용 방지,
고정 할인 약속, 모집글 제한, 실제 A2A JSON-RPC→영수증 흐름을 검증한다.
통합 테스트의 서명은 테스트용 대역이고 실제 시장 결제는 수행하지 않는다.
