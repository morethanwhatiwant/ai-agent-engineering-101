# 상품과 거래 근거 중심의 소개·광고

참고: 공개 /api/board의 상위 가게 소개와 /api/forum의 최근 글.
- dae-yangkim: 상품명/SKU 문의 방법, 등급·인증·보증을 앞에 표시.
- yms979: 실제 재고와 품질 조건을 설명. 포럼에는 실구매 가격·정가 대비 차이·등급·거래번호를 게시.
- jiseokkk: 정산된 상품·가격·등급과 품질 주장 일치 여부를 간결하게 게시.
이는 관찰한 형식이며, 그 문구 때문에 상위권이라는 인과관계를 확인한 것은 아니다.

## 교수님 공유 공지 반영
출처: 사용자가 전달한 Round 3 시작 후 2시간 13분 시점의 DB 기반 공지.
공지 수치는 그 시점의 관측값이며 현재 값이나 우리 실적이 아니다.

- 초기 적자만으로 실패를 판단하지 않는다. 재고 회전과 회수 시간이 중요하다.
  소개에서 물건이 잘 팔린다고 근거 없이 주장하지 않는다.
- 보증 거래와 환불이 실제 발생했다. 우리 비식품은 현재 보증 없음으로 명시한다.
  보증 6h/24h 같은 경쟁사의 조건을 복사해 제공한다고 주장하지 않는다.
- 서명 없는 영수증은 정산되지 않았다. 우리 소개는 시장 인증서를 결제 단계에서
  확인 가능하다고 안내한다. 실제 구현은 영수증 서명과 kit 정산을 유지한다.
- 식품의 필요 보관시간이 중요하다. 실제 잔여 시간을 견적과 광고에 표기한다.
- 포럼에는 실제 가격·등급·정산 번호를 쓴다. 프롬프트 인젝션, 운영자 사칭,
  별점 강요, 가짜 후기, 근거 없는 최저가 문구는 넣지 않는다.
- 게시 수만 늘리기 위한 반복 글 대신 재고 상품 두 개를 교대로 소개하고,
  실구매 기록과 번갈아 게시한다. 기존 10분 간격/하루 12건 상한은 유지한다.
- 공지의 마진 중앙값 33%는 계산 분모가 불명확해 가격 공식으로 적용하지 않는다.

## 구현
shop_copy.py: 소개·재고 광고·실구매 기록 문구.
referral_seller.py: 상품 중심 Agent Card, 견적의 등급·남은 시간·보증 여부.
buyer_publicist.py: 서로 다른 SKU 최대 2개 광고, 이전 광고 상품 회피,
정산 완료+결과 기록이 있는 실제 구매만 후기 후보로 사용, 거래번호 중복 게시 방지.
광고는 같은 운영자임을 밝히며, 구매 기록은 우리 바이어의 실제 타 가게 구매다.
정가 대비 할인은 내림 표시하고, 정가 이상 가격에 할인이라고 쓰지 않는다.

이미 실행 중인 seller와 buyer 연구 워커는 모듈을 메모리에 유지하므로
새 소개·문구 적용에는 각각 한 번 재시작이 필요하다. 발행 이력과 제한 카운터는 초기화하지 않는다.
